# Alpha v5 durability and receipt identity

Alpha remains SHADOW_ONLY. These protocols grant no broker or CAPITAL authority.

## State machine

| State | Evidence | Permitted next step |
|---|---|---|
| ABSENT | Initial open establishes no file or no named transaction | Append the initial intent; no dispatch or terminal acknowledgement |
| READABLE_UNCONFIRMED | A complete row or identity receipt is readable | Validate exact identities under the writer lock, then synchronize |
| CONFIRMED | File synchronization and every ancestor directory synchronization succeeded for the same observed file generation | Dispatch after confirmed PREPARE; publish terminal processed acknowledgement only for the exact confirmed prediction |
| UNKNOWN | Read, metadata, write, synchronization, identity, or lock failure | Remain nonterminal and retry the actual barrier when storage recovers |

Every reader, including a restarted process, begins with unconfirmed knowledge.
There is no persistent “fsync succeeded” flag and no receipt chain purporting to
prove its own durability. A readable COMMIT whose fsync failed may recover only
when a later synchronization barrier actually succeeds. Recovery does not need
to append another receipt if its identity row is already present.

A prediction without its identity receipt remains nonterminal. The append path
may finish that missing receipt while preserving the original prediction ID.
The successful append crosses the barriers; if it fails, repeated reads and
restarts confer no authority.

## Exact identity

New receipts use `atlas-alpha-receipt-v2`, include the exact target identity,
and bind SHA-256 of the entire canonical preceding PREPARE/PREDICTION row.
Verification requires the declared schema, complete typed fields, an aware
receipt timestamp, a unique preceding target, matching snapshot and analysis
identities, matching prediction identity for COMMIT, and the exact row digest.
A malformed receipt blocks; another valid row does not sanitize it.

Historical v4 receipts remain immutable. Only their exact supported v1 field
set is recognized: schema, kind, aware timestamp, analysis identity, snapshot
identity, and prediction identity for COMMIT. Every declared identity must
match a unique preceding row of the expected schema and kind. Unknown fields,
unknown versions, missing identities, and mismatches refuse. Compatibility
never bypasses actual synchronization; a v1 receipt is a reference to an
immutable row, not a durability certificate. New writes always use v2.

The committed view is read under one lock. It records file device/inode, size,
mtime, ctime, and link count from the read descriptor, compares the named file,
and requires the same generation before and after the synchronization barrier.
Metadata uncertainty after opening a file cannot become ordinary absence.

## Append-only retries and writer topology

A historical `BUDGET_EXHAUSTED` prediction can be superseded by a new attempt
that names `supersedes_prediction_id`. The old prediction and receipt remain
byte-for-byte unchanged. A completed economic analysis cannot be superseded.
One synchronized committed view selects the effective attempt for restart
reconciliation.

All appenders retain short-write/EINTR handling and torn-tail separation. They
synchronize directory names on every retry, including every ancestor created
by `makedirs`; visible parent directories do not prove durable names.

Relative and symlink aliases contend on the same canonical sidecar lock.
Hardlinked authority files are explicitly unsupported and fail closed at
locking, append, and synchronization. This avoids independent sidecars for two
names of the same inode. Locks are local POSIX advisory locks; cooperating
writers share this protocol. A shared filesystem across multiple hosts still
requires an independently justified distributed writer model.

## Reproduction

`tests/test_astra_v5_durability.py` retains the original repeated-failure and
receipt-identity witnesses plus restart, process death, nested-directory,
generation-change and alias variants. The legacy fixture was generated by the
exact rejected v4 writer, not by a v5 approximation. Its checked-in manifest
binds its bytes and source commit. Regenerate into a new disposable directory:

```sh
python tools/astra_v5_legacy_fixture.py --v4-source /path/to/exact-v4-checkout --output /new/disposable/output
```

The generator and tests use only synthetic inputs and local files. Filesystem
fault injection and process death establish software behavior; they do not
claim a physical power-loss or Railway-volume restart proof.
